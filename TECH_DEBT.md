# Technical Debt Register

Every `TODO`, `FIXME`, `HACK`, and `XXX` in application source must use a
`TD-###` identifier listed here. `npm run check:tech-debt` verifies the link.

| ID | Location | Debt | Resolution criteria |
| --- | --- | --- | --- |
| TD-002 | `lib/services/notifications/` | The vendored Awesome Notifications copy ships duplicated blocks (single/double slider widgets, repeated `notifications_util.dart` patterns, and `common_functions.dart` vs `common_web_functions.dart`); these clones are grandfathered in `.jscpd-baseline.json` (fingerprints refreshed in place after the `dart format` commit shifted line breaks; same 16 clones, no new duplication). | Unify or deliberately exclude the vendored duplication, then shrink `.jscpd-baseline.json`; do not let the clone count grow. |
| TD-003 | `lib/database/anychat_user.dart` (`findUserByEmail`), `firestore.rules` (`users/{uid}`) | Profile `email` is self-asserted: the owner may write any address. Apple sign-up refuses with "email in use" when any profile carries the address, so one user can block another's Apple registration or impersonate them in email search. | Bind `email` to `request.auth.token.email` in the rules (or stop letting clients write it), and/or move the duplicate-email check server-side; add emulator tests for the spoofing case. |
| TD-004 | `lib/database/anychat_user.dart` (`AnyChatUser.fromSnapshot`), `firestore.rules` (`profileFields`) | Profile writes are limited by key but not by type or size. A non-string or over-35-character `language` makes `createConversation`/`addUserToConversation` fail for anyone adding that user (their info docs fail `isValidConversationInfo`), and wrong types break the `as String?`/`as bool?` casts other clients use when reading profiles. | Type- and size-check `displayName`, `email`, `photoUrl`, `language`, `blockedAccounts`, `theme`, `notificationsEnabled`, and `emailVerified` in the rules, with emulator tests for accepted and rejected shapes. |
| TD-005 | `functions/sms_bridge.js` (`createSmsRelay`) | The outbound relay sends from the trigger snapshot without claiming the message first. Firestore triggers are at-least-once, so a redelivered event sends (and bills) the same SMS twice. | Transactionally move `smsStatus` from `pending` to a claimed state before calling alpha-text, skip messages already claimed, and cover redelivery in `functions/test/sms_bridge.test.js`. |
